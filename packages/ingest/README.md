# @su-maek/ingest — 교재 PDF 반입

문제집 PDF에서 문항을 뽑아 문제은행에 넣기 위한 추출기.

## 왜 두 단계인가

```
PDF ──(python/extract.py)──▶ 기하 덤프 JSON ──(src/)──▶ 문항
     PyMuPDF, 해석 없음                      해석 전부
```

파이썬 쪽은 **해석하지 않는다.** "종이에 무엇이 어디에 있었나"만 옮긴다.
문항을 나누는 것도, 수식을 푸는 것도, 선택지를 묶는 것도 TypeScript에서 한다.

경계를 여기 둔 이유:

- 해석에는 테스트가 필요하다. 저장소의 계약·게이트·뮤테이션 검증은 전부 TS에
  있다. 파이썬으로 넘어가는 순간 그 그물 밖이다.
- 원문(`math_expressions.raw_source`)은 불변이어야 한다(원칙 2O). 추출기가
  수식을 "고쳐서" 넘기면 원문이 사라진다.

## 쓰는 법

```bash
python packages/ingest/python/extract.py "교재.pdf" -o dump.json --from 2 --to 33
pnpm --filter @su-maek/ingest extract dump.json --expect=1-213 --verbose
```

`--expect`는 **인쇄된 문항 번호 구간**이다. 이게 없으면 채점은 뽑힌 것만 본다
— 통째로 빠진 문항은 채점표 어디에도 나타나지 않는다. 실제로 8문항짜리 한 쪽으로
100%를 받고도 1단원 전체로는 35문항을 흘리고 있었다.

**모든 CLI는 `--이름=값` 등호 형식만 읽는다.** 공백으로 띄우면(`--expect 1-213`)
오류 없이 무시된다.

처음부터 끝까지의 재현 절차, 재적재 방법, 남은 일은 [../../docs/handoff.md](../../docs/handoff.md)에 있다.

## 검사는 둘이다

**렌더가 통과했다는 것은 「그려진다」는 뜻이지 「맞다」는 뜻이 아니다.**
`A=2b\times 3^{b}\times 5c`는 KaTeX가 아무 오류 없이 예쁘게 그리지만 지면은
`A=2^a×3^b×5^c`다. 학생은 틀린 풀이를 읽고, 화면 어디에도 표시가 없다.

| 도구 | 묻는 것 |
|---|---|
| `audit-katex` | 그려지는가 (DB를 읽는다) |
| `audit-content` | **지면과 같은가** (덤프를 읽는다) |

```bash
pnpm --filter @su-maek/ingest audit-content --book=book.json --answers=answers.json
pnpm --filter @su-maek/ingest audit-katex --verbose
```

`src/audit.ts`의 규칙 7종은 전부 실제로 한 번씩 틀렸던 것이다. 규칙을 더할 때는
**거짓 양성을 반드시 확인할 것** — 처음 만들었을 때 264건 중 상당수가 규칙 자체의
오검출이었다(`120m`을 「120의 위첨자 m」으로 읽었다).

## 교재별 추출 프로파일

문제집마다 조판이 다르다. 단 수, 문항 번호의 폰트·크기, 수식 폰트 계열,
선택지 기호, 유형 머리글이 전부 다르다. 그걸 파서 본문에 흩어 두면 두 번째
교재를 붙일 때 첫 교재가 깨진다. `src/profiles/`에 교재별로 모아 둔다.

| 프로파일 | 교재 | 확인된 특징 |
|---|---|---|
| `rpm-2022` | 개념원리 RPM (2022 개정) 학생용 | 아래 참조 |

### rpm-2022 — 실측 기록

- **텍스트 레이어가 살아 있다.** OCR이 필요 없다 (184쪽, 평균 999자/쪽).
- **수식과 한글이 폰트로 완전히 갈린다.** 수식 `EH*` 계열, 한글 `YDVY*`·`SMSS*`.
  수식 구간을 추측할 필요가 없다 — 이 교재가 반입하기 쉬운 가장 큰 이유.
- **단 수가 쪽마다 다르다.** 「유형 익히기」는 2단, 「개념 익히기」는 2단 안에
  다시 2열 격자가 들어가 사실상 4단. 문항 번호의 x좌표를 뭉쳐 쪽마다 알아낸다.
- **문항 번호가 쪼개져 온다.** `"0"` + `"131"`, 뒤에 제어문자가 붙기도 한다
  (`"187 \b"`). 붙이고 제어문자를 턴 뒤에 판정해야 한다.
- **지수가 오는 방식이 셋이다.** ① 전용 글리프(`Û`=², `º`=ᵇ) ② 크기가 절반인
  별도 span(5.3~5.99pt, 위로 올라앉는다) ③ **폭 0인 글자로 앞 글자에 겹쳐 찍힌다.**
  ③이 고약하다 — 위첨자 `a`가 코드 `b`로 오고 본문의 변수 b와 구별이 안 된다.
  가르는 것은 **폭**뿐이다. 높이로는 못 가른다: PyMuPDF의 글자 상자는 글리프의
  잉크가 아니라 줄 높이를 준다(한 줄의 여덟 글자가 전부 같은 y).
- **같은 코드가 글꼴마다 다른 글자다.** EHyak의 `y`는 말줄임(⋯)이지만 EHsang의
  `y`는 변수 y다. `¾`도 EHyak에서는 ≥, EHsang에서는 ℃다. 글꼴을 안 보고 옮기면
  발문이 「어떤 자연수 ⋯의 제곱」이 된다.
- **흰 글자가 섞여 있다.** 고쳤다가 지우지 않은 조판 흔적이다. 지면에는 안 보이는데
  텍스트 층에는 있어서 `2)6`이 `2)46`이 됐다. 다만 「답」 배지처럼 **칠한 바탕 위의**
  흰 글자는 진짜 글자다 — 두 책 1217개 중 1205개가 그랬고, 맨 종이 위 12개만
  흔적이었다. 판정 근거는 글꼴이 아니라 바탕이다(`src/ink.ts`).
- **표를 그림으로 그린다.** 세로셈 `3)117`의 괄호와 윗줄은 EHboNA 글리프 조각이고,
  약수 격자표의 경계는 **칠한 사각형**이다. 표라는 사실을 버리면 숫자가 이어 붙어
  무슨 계산인지 알 수 없게 된다 → `\begin{array}`로 옮긴다.
- **2행 분수는 텍스트에 흔적이 없다.** 분자·분모가 별개 span이고 사이의 막대는
  높이 0인 벡터 선분이다. 그 막대가 유일한 근거다.
- **난이도 뱃지(대표문제·중하·중·상)는 벡터 그림이다.** 텍스트로 못 뽑는다.
  검수 때 사람이 지정하거나 위치로 추정해야 한다.
- **구매자 이메일이 워터마크로 박혀 있다.** 쪽마다 텍스트 레이어에 들어 있고
  문항 본문에 섞인다. 반드시 걸러야 한다.
- 정답은 본책에 없다. 별책 『정답 및 해설』이 문항 번호 100% 일치.

## 수식 해독표

`src/hwp-encoding.ts`. 국내 교재 PDF의 수식은 유니코드가 아니라 조판기 전용
폰트의 코드포인트다. 눈에는 2²×3³이지만 파일에는 `2Û`_3Ü``라고 적혀 있다.

**표의 값은 추측이 아니라 지면 대조 또는 산술로 확정한 것이다.**
`ß`=6과 `à`=7은 계산으로 증명됐다 — `3Þ`_51=3Þ`_3_17=3ß`_17`에서 3⁵×3=3⁶,
`128=2à``에서 2⁷=128. 확인하지 않은 글리프는 표에 **넣지 않는다.** 모르는
글리프는 버리지 않고 `unknown`에 담아 올린다. 조용히 지우면 `2×3`이 `23`이
되어 문항이 멀쩡해 보인다.

## 자가채점

"잘 뽑힌 것 같다"는 판단은 쓸 수 없다. 흘린 줄은 결과물에 없으니 눈에도
안 띈다. 그래서 채점 항목을 지면과 대조할 수 있는 것으로만 잡았다:

- **인쇄 번호 커버리지** — 인쇄된 문항 중 몇 개를 건졌나 (누락 탐지의 핵심)
- **span 커버리지** — 지면의 글자가 전부 설명됐나 (문항에 들어갔거나, 문항이
  아니라고 판단했거나). 설명되지 않은 것이 곧 조용한 누락이다.
- **수식 렌더** — `@su-maek/core/math`의 KaTeX 게이트를 그대로 쓴다
- **수식 파편·고아 위첨자·머리글 유입·발문 길이·한 단 이탈**
