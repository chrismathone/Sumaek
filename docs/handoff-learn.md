| 2 | 예정 테스트가 상태에 안 잡혀 화면이 두 줄 사이에서 모순됐다 | `StepState`에 `upcoming` 추가 |

가장 잘 보이는 자리에서 깨져 있었다. 주석과 코드를 대조하지 않으면 안 보인다.

**2번의 함정**: `upcoming`을 더할 때 `readDay`의 `hadWork`를 `!== "none"`으로 두면

## 3. 하려던 것 — 개념 중심 통합 (미구현)

### 3.1 무엇을

지금은 개념 공부·개념 인강·연습문제가 **각각 다른 단계이자 다른 화면**이다. 학생은 같은
개념을 배우면서 세 화면을 오간다. 사용자 요청은 「따로 단계 두지 말고 개념을 열어놓고
인강 시청」, 그리고 「연습문제도 해당 개념·인강에 배정해서 이어서 풀어볼 수 있게」다.

그리려던 모양:

```
1단계  오늘 배울 것
2단계  개념 학습   ← 읽기 + 인강 + 연습을 개념 단위로 묶은 한 단계
3단계  테스트
4단계  복습
```

화면(`/learn/study`)은 **자료 단위가 아니라 개념 단위로 넘긴다**. 한 쪽 = 한 개념이고,
그 안에서 개념 본문 → 인강 임베드 → 연습문제 순으로 이어진다.

### 4.3 이 수치를 다시 뽑는 SQL — 기대값 213 · 197 · 197

```sql
-- 오늘 차시 개념 + 게이트 통과 수
with today_concepts as (
  select distinct cc.concept_id::uuid as id
  from learner_schedule_items li
  cross join lateral jsonb_array_elements_text(li.planned_node_ids) as n(node_id)
  join route_nodes rn on rn.id = n.node_id::uuid
  cross join lateral jsonb_array_elements_text(rn.concept_ids) as cc(concept_id)
  where li.item_date = (now() at time zone 'Asia/Seoul')::date
), q as (
  select distinct q.id, q.review_status::text as rs,
         coalesce(r.status::text, 'none') as rights
  from question_alignments a
  join today_concepts t on t.id = a.concept_id
  join questions q on q.id = a.question_id
  left join content_rights r on r.id = q.content_right_id
  where a.provenance <> 'ai_suggested'   -- 미검수 AI 제안은 학생에게 안 나간다
)
select count(*) filter (where true)                                    as 정렬,
       count(*) filter (where rs = 'published')                        as 검수통과,
       count(*) filter (where rs = 'published' and rights = 'usable')  as 출제가능
from q;
```

### 4.5 연습 자료 행 — `seed-unit1-demo` 4단계가 됐다

1단원 개념 5종에 **연습 자료(`learning_materials`, `kind='practice'`) 5행**을 만들었다.
이번에는 1회성이 아니라 **`packages/db/scripts/seed-unit1-demo.mts`의 4단계로
들어갔다** — 멱등이고(있으면 어떤 상태든 건드리지 않는다 — 교사의 큐레이션·보관
결정을 시드가 되돌리면 안 된다), DB를 다시 세워도 재현된다.

- `question_ids`는 빈 배열 — `listPracticeQuestions`가 그 개념의 출제 가능 문항에서
  `created_at` 순 5건을 자동 선별한다(`learning-material.ts:210-227`).
- 제목은 「{개념명} 연습」 — 문항 수를 제목에 넣지 않는다(자동 선별은 풀이 줄면 함께
  주는데 제목의 숫자는 안 준다).
- 실행 실측: 생성 5 · published 5 · 2회차 실행 생성 0(멱등 확인).

**화면 실측 (2026-08-04)**: `/learn/today` 4단계가 「없음」→「남은 5건」, 히어로의
「할 차례」는 여전히 화면에 한 번. `/learn/practice`는 개념 5종 × 문항 5건 렌더,
콘솔 오류 0.

**자동 선별의 배선 — 같은 날 소유자 지적 두 건으로 다시 고쳤다:**

1. **전담 정렬 우선 (「개념 공부와 일치하는 연습」).** 처음 배선은 `created_at` 순
   5건이라 교재 맨 앞의 소수 판별 문항이 **모든** 개념의 연습에 나왔다(한 문항이
   여러 개념에 정렬 — 4.1절의 379 > 213). `question_alignments.weight`가 이미
   특이성을 담고 있다: 전담 정렬은 1.0, 여러 개념에 걸치면 0.33…으로 분산
   (개념 5종 모두 전담 게시 문항 12건 이상 — 실측). 자동 선별을
   `order by max(weight) desc, created_at`으로 바꿔 소인수분해 연습에는 소인수분해
   문항이 나온다. `learning-material.ts`의 자동 분기.
2. **채점 불가능형 제외 (`autoPickable`).** 정답 정보가 없는 문항 · **복수 정답
   객관식**(화면이 라디오 단일 선택이라 맞힐 방법이 없다 — #0049·#0062 실측) ·
   다항 나열(⑴⑵…)·줄바꿈·40자 초과 정답 · **분수·근호 꼴 정답**(`\frac` — 일반
   텍스트 입력으로 같은 표기를 만들 수 없다)은 자동 선별에서 뺀다. 문제은행에는
   그대로 있다 — 교사 지정(questionIds)은 거르지 않는다.

**답 입력과 채점 — 「◯를 키보드로 어떻게 넣지」(소유자 지적):**

- 판별 문항(정답이 ◯·△·×)은 **칩이 유일한 입력**이고, 발문도 지면의
  「()안에 써넣으시오」에서 「고르시오」로 **표시만** 전환된다(DB 원본 불변,
  지면의 답 빈칸 꼬리 「11()」의 () 제거 포함 —
  `apps/web/src/lib/learn/symbol-answer.ts` 순수 함수, 테스트 7건).
- 칩은 **발문이 언급한 기호만** 낸다: 소수 판별은 ◯·△, 진위 판별은 ◯·×.
  진위 문항에 △ 칩이 있으면 뜻 없는 답이 가능해진다(소유자 지적). 기호 쌍은
  발문에 이미 적혀 있으므로 정답 유출이 아니다. 쌍을 못 읽으면 셋 다 낸다.
- 채점기가 **기호 동치류**를 인정한다: ◯≡○≡O≡o≡ㅇ, ×≡x≡X≡✕, △≡▲ —
  **기준이 기호일 때만**(기준이 숫자 0이면 o는 오답 그대로). 비수치 서술 답은
  공백 차이 무시(「밑: 2, 지수: 5」), 식 답은 한 글자 지수의 중괄호·×/\* 표기 관용
  (`2^{2}\times 3^{2}` ≡ `2^2×3^2`). `packages/core/src/grading/` — 테스트 6건 추가,
  기호 동치는 변이 검증 통과.
- **화면 실측**: 칩으로 5/5 정답, 칩 4 + 식 타이핑 「2×5」 혼합 5/5 정답. 채점 후
  입력값 유지(컨트롤드 입력 — React 19 폼 리셋에 답이 지워지던 것도 함께 해소).

**검증반 일정은 10:00–22:00이다 (09:00이 아니다).** 09–10시는 db:seed(080·081)와
e2e materials.spec이 같은 학생에게 쓰는 칸이라, 09시부터 잡으면 배타 제약으로 세
도구가 서로를 죽였다([handoff-project.md](handoff-project.md) 4.4절의 미해결 충돌).
10시 시작으로 배타 충돌은 없다. 그리고 **오늘은 1단원으로 통일한다** — 시드
5단계가 검증반 외의 오늘 개별 항목(가감법 데모 080 — **가감법은 중2 내용**이라
중1 서사에 섞이면 안 된다, 소유자 결정 2026-08-04)을 치운다. db:seed·e2e가
되살리든, **route-builder류 「개별 일정 계산」이 루트에 없는 항목을 지우든**(제품
동작), 화면이 이상하면 범인 찾기 전에
`pnpm --filter @su-maek/db seed-unit1-demo`를 다시 돌리는 것이 정답이다(멱등 수렴).

**교사 쪽 배선 실측 (2026-08-04)**: `/app/today` 오늘 수업 = **1단원 검증반 (중1)
