# 그림 문항 — SVG로 세우기 (설계 + GPT 프롬프트 목록)

> 작성 2026-08-05 · 대상: RPM 중1-1 반입분 1123문항 중 **그림 문항 55건**
> 관련: [handoff.md](handoff.md) 7.2 · [../packages/ingest/README.md](../packages/ingest/README.md)

지금 그림 문항은 `figureBoxes`·`figureLabels`를 `source_ref`에 남기고
`layout_review_required`로 격리하는 데까지만 되어 있다. **화면에는 그림 없이
나간다.** 이 문서는 그 55건을 무엇으로, 어떤 순서로 세울지와, 사람이 손으로
그릴 수 없는 것을 GPT에 맡길 때 쓸 프롬프트를 담는다.

---

## 1. 이미 있는 자산 — 새로 짜지 않는다

두 저장소에 **이미 검증된 SVG 생성기**가 있다. 둘은 같은 뿌리다
(mathg-gen 쪽 주석에 「mathlab 1:1 이식」이라고 적혀 있다).

| 어디 | 무엇 | 규모 |
|---|---|---|
| `D:\mathlab\src\lib\utils\svg-diagrams\` | 렌더러 **24종** + 디스패처 | 초등 13(수직선·분수원·시계·막대·꺾은선·띠·원그래프·각도·자릿값·점배열·순서도·그림그래프) · 중등 11(좌표평면·함수그래프·다각형·도형·입체·전개도·히스토그램·줄기잎·산점도·벤다이어그램·수형도) |
| `D:\mathg-gen\src\lib\diagram\` | 같은 것의 **정리된 이식본** | 7종(triangle·circle·coordinatePlane·quadrilateral·polygon·solid·composite) + `normalize`·`validate`·`eval-expr` |
| `D:\mathg-gen\src\services\ai\prompts.ts` | **AI inline SVG 프롬프트** (실전 운용 중) | viewBox·글꼴·라벨 겹침 규칙까지 |

**둘의 성격이 다르다.**

- mathlab 쪽이 **종류가 많다**(24종). 중1-1에 필요한 수직선·꺾은선 그래프가
  거기에만 있다.
- mathg-gen 쪽이 **구조가 낫다.** `normalize.ts`가 「AI가 부정확한 좌표를
  줘도 프리셋에서 정확한 좌표를 다시 계산」한다. 이게 핵심이다 —
  **AI에게 SVG를 시키지 않고 spec(JSON)을 시킨 뒤 좌표는 우리가 계산한다.**
  AI가 좌표를 틀리면 그림이 조용히 어긋나는데, 그건 우리가 가장 싫어하는
  종류의 오류다(렌더는 성공하고 뜻만 틀린 것).

> **가져올 것**: mathg-gen의 `src/lib/diagram/` 구조를 뼈대로 하고,
> mathlab의 `number-line`·`line-graph`·`function-graph`를 그 스키마에 맞춰
> 옮긴다. 둘 다 순수 함수라 의존성이 없다.

## 2. 55건은 세 갈래다 — 실측 분류

`figureBoxes`가 잡힌 55건을 전부 지면과 대조해 나눴다. **가장 큰 발견은
절반 가까이가 그림이 아니라 표라는 것이다.**

| 갈래 | 건수 | 어떻게 | 왜 |
|---|---|---|---|
| **A. 표** | 19 | SVG 아님 — 구조화 표 블록 | 표를 그림으로 만들면 화면 크기에 안 맞고, 읽기 프로그램도 못 읽고, 값만 바꾸는 변형 출제도 막힌다 |
| **B. 좌표평면·그래프** | 25 | 프리셋 spec (결정적 생성) | 격자·축·눈금이 전부 같은 규격이다. AI가 손댈 곳이 없다 |
| **C. 진짜 그림** | 11 | 사람 또는 GPT | 상황도·입체·용수철 등 |

### A. 표 19건 — SVG로 만들지 말 것

```
0031 0492 0493 0499 0558 0559 0668 0807 0814 0815
0892 0908 0923 0984 1002 1026 1059 1062 1107
```

지면에서 괘선이 벡터라 「그림」으로 잡혔을 뿐, 내용은 전부 표다
(0892·0908은 달력, 0814·0815는 거리·속력·시간/농도 표, 나머지는 x·y 대응표).
`figureLabels`에 셀 값이 이미 순서대로 들어 있다 —
예: `1026` → `x/y 1/A B/-6 3/-9 4/-12 5/C`.

**할 일**: 본문 블록에 `table` 종류를 더하고(현재 `paragraph`·`condition_box`·
`choice_group` 3종뿐) `figureLabels`를 행·열로 되세운다. 격자표 복원은
`answers.ts`의 `mergeGridTables`가 이미 하는 일이라 그 규칙을 본책 쪽으로
옮기면 된다.

### B. 좌표평면·그래프 25건 — 프리셋으로 결정적 생성

| 꼴 | 문항 | 필요한 spec |
|---|---|---|
| 빈 격자 좌표평면 (−4~4) | 0996 0997 0998 0999 1014 1016 1017 | `coordinatePlane` + `functions:[{expr}]` |
| 점이 찍힌 좌표평면 | 0917 0918 0934 0935 0970 1084 | `coordinatePlane` + `points` |
| 정비례·반비례 그래프 | 1036 1041 1073 1115 | `coordinatePlane` + `functions` + 교점 `points` |
| 실생활 꺾은선 | 0959 0960 0968 0969 0983 1096 1097 1123 | `coordinatePlane` + `lines` + 축 단위 라벨 |
| 수직선 | 0404 0916 | mathlab `number-line` 이식 |

**이 25건에는 GPT가 필요 없다.** 발문과 `figureLabels`에 좌표가 이미 글자로
있다 — 0934의 라벨은 `4 y B 2 -4 -2 E/O 2 4 x C -2 D -4`이고, 여기서 축
눈금(−4·−2·2·4)과 점 이름(A~E)이 전부 나온다. 점의 **위치**만 지면에서
읽어 spec에 적으면 된다.

> 다만 눈으로 한 번은 봐야 한다. 라벨 문자열만으로는 점 A가 (2,3)인지
> (3,2)인지 알 수 없다. `render-page.py --clip`으로 그 자리를 잘라 보는
> 절차는 이미 있다 — 문항마다 clip 좌표가 `source_ref.figureBoxes`에 있다.

### C. 진짜 그림 11건 — 여기만 GPT

```
0030  소인수분해 세로셈 (표에 가깝지만 괄호 조판)
0148  직육면체에 쌓은 벽돌 (가로 120·세로 60·높이 90)
0596  넓이를 구하는 합성 도형 두 개
0657  사다리꼴에서 색칠한 부분
0684  큰 정사각형 안의 작은 직사각형 (색칠)
0900  잔디밭 사이의 길 (폭 6m·xm)
0913  정사각형 종이를 겹쳐 이어 붙이기
1034  직사각형 ABCD 위를 움직이는 점 P
1118  용수철에 매단 추
0959  물을 채우는 그릇 두 개 (모양이 뜻이다)

이 중 **0148·0596·0657·0684·0900·0913·1034는 프리셋으로도 된다**
(`quadrilateral`·`polygon`·`solid`). GPT는 **0959·0960·1118** 셋과,
프리셋으로 억지스러운 것에만 쓴다.

## 3. GPT를 쓸 때의 원칙

mathg-gen이 실전에서 배운 것이 프롬프트에 박혀 있다. 그대로 가져온다.

1. **SVG를 직접 시키지 말고 spec을 시킨다.** 좌표 계산은 우리 코드가 한다.
   spec으로 표현할 수 없는 것에만 inline SVG를 허락한다.
2. **라벨은 값이 아니라 자리다.** 숫자를 그림에 박으면 변형 출제(숫자만
   바꿔 재출제)가 막힌다. 라벨은 spec의 필드로 두고 렌더에서 채운다.
3. **렌더 성공은 정확성이 아니다.** SVG는 문법이 맞으면 무엇이든 그린다.
   지면 이미지와 나란히 놓고 사람이 확인하기 전에는 게시하지 않는다
   (`refine-concepts`의 나란히 보기와 같은 게이트).
4. **못 그리겠으면 비워 둔다.** 그럴듯한 그림이 틀린 그림보다 나쁘다.
   0166·0184에서 「답을 못 읽으면 비워 둔다」와 같은 규칙이다.

## 4. 프롬프트 목록

각 프롬프트는 **입력이 정해져 있다**: 발문 텍스트 + `figureLabels` +
지면 크롭 이미지(`render-page.py --clip`). 출력은 spec JSON이다.

### P0. 공통 머리말 (모든 프롬프트 앞에 붙인다)

```
너는 중학교 수학 교재의 그림을 **좌표 spec(JSON)**으로 옮기는 일을 한다.
SVG를 직접 쓰지 마라 — 렌더러가 spec에서 좌표를 다시 계산한다.

지켜야 할 것:
1. 지면에 **있는 것만** 옮긴다. 보이지 않는 보조선·눈금·라벨을 더하지 마라.
2. 숫자 라벨은 값을 그대로 옮긴다. 반올림·단위 변환 금지.
3. 확신이 없는 값은 그 필드를 **비워 둔다.** 채워 넣지 마라.
   비어 있으면 사람이 검수하지만, 틀린 값은 아무도 모른다.
4. 출력은 JSON 하나뿐. 설명·주석·코드펜스 금지.

입력으로 주는 것:
- 문항 발문 (수식은 $…$)
- 지면에서 뽑은 라벨 문자열 (읽는 순서대로, 위치 정보 없음)
- 그림 영역 크롭 이미지
```

### P1. 좌표평면 — 점 찍기 (0917 0918 0934 0935 0970 1084)

```
<P0>

이 그림은 좌표평면 위에 점이 찍힌 것이다. 다음 스키마로 옮겨라.

{
  "type": "coordinatePlane",
  "xRange": [최소, 최대], "yRange": [최소, 최대],   // 축에 찍힌 눈금 끝값
  "showGrid": true,
  "points": [ { "coord": [x, y], "label": "A" }, … ]
}

규칙:
- xRange·yRange는 **축에 실제로 인쇄된 눈금**의 끝값이다. 보통 [-4,4]다.
- 점의 좌표는 격자 교점으로 읽는다. 격자 사이에 걸쳐 있으면 그 점의
  coord를 비우고 label만 남겨라 — 사람이 채운다.
- 원점 라벨 O는 렌더러가 그린다. points에 넣지 마라.

검증: 점의 개수가 발문에 나온 점 이름의 개수와 같은가?
```

### P2. 좌표평면 — 정비례·반비례 그래프 (0996~0999 1014 1016 1017 1036 1041 1073 1115)

```
<P0>

이 그림은 정비례 y=ax 또는 반비례 y=a/x 관계의 그래프다.

{
  "type": "coordinatePlane",
  "xRange": [-4, 4], "yRange": [-4, 4], "showGrid": true,
  "functions": [ { "expr": "-2*x", "label": "y=-2x" } ],
  "points": [ { "coord": [x, y], "label": "A" } ]   // 교점·지나는 점만
}

규칙:
- expr는 **발문의 식**을 그대로 옮긴다. 그림에서 기울기를 눈으로 재지 마라
  — 발문에 y=-2x라고 적혀 있으면 그것이 사실이다.
- 반비례는 "a/x" 꼴로 쓴다. x=0에서 끊기는 것은 렌더러가 안다.
- 그래프가 여러 개면 functions 배열에 순서대로. 지면의 ①②③ 번호는
  label에 넣는다.
- **식이 발문에 없고 그림에만 있으면** functions를 비우고, 지나는 점만
  points에 넣어라. 기울기를 짐작해 식을 지어내지 마라.
```

### P3. 실생활 꺾은선 그래프 (0959 0960 0968 0969 0983 1096 1097 1123)

```
<P0>

이 그림은 시간에 따른 변화를 나타낸 꺾은선 그래프다. 격자가 없거나
축 단위가 수학 좌표가 아니다(분·km·kcal·℃ 등).

{
  "type": "coordinatePlane",
  "xRange": [0, 최대], "yRange": [0, 최대],
  "showGrid": false,
  "axisLabels": { "x": "시간(분)", "y": "거리(km)" },
  "lines": [ { "from": [x1,y1], "to": [x2,y2], "label": "민준" } ],
  "points": [ { "coord": [x,y] } ]                 // 축에 인쇄된 눈금점만
}

규칙:
- 축 라벨은 **괄호까지 그대로**다 — "거리(km)"이지 "거리"가 아니다.
- 꺾은선은 꺾이는 점마다 선분 하나로 쪼개 lines에 넣는다.
- 눈금이 없는 축(모양만 보여 주는 그래프)은 xRange·yRange를 비우고
  lines의 좌표를 0~10 사이 상대값으로 준 뒤 그 사실을 label에 적어라.
- **두 그래프를 비교하는 문항**(0968 0969 1096 1097 1123)은 선마다 label을
  반드시 넣어라. 어느 선이 누구인지가 문제의 전부다.
```

### P4. 수직선 (0404 0916)

```
<P0>

이 그림은 수직선이다.

{
  "type": "numberLine",
  "min": -5, "max": 5, "step": 1,
  "points": [ { "value": -3, "label": "A", "filled": true } ],
  "arrows": [ { "from": 0, "to": 4, "label": "+4" } ]   // 덧셈 화살표
}

규칙:
- min·max는 인쇄된 눈금의 양 끝이다.
- 분수 위치(7/2 등)는 value에 소수로 쓰지 말고 문자열 "7/2"로 둔다.
- 화살표는 **방향이 뜻이다.** 왼쪽으로 가는 화살표는 from > to로 쓴다.
```

### P5. 평면도형 — 넓이·길이 (0596 0657 0684 0900 0913 1034)

```
<P0>

이 그림은 넓이나 길이를 묻는 평면도형이다. 색칠한 부분이 있으면 그것이
문제의 핵심이다.

{
  "type": "polygon",
  "vertices": [[x,y], …],                    // 왼쪽 아래부터 시계 반대 방향
  "vertexLabels": ["A","B","C","D"],
  "showLengths": [ { "edge": [0,1], "value": "10cm" } ],
  "rightAngleMarks": [0, 1, 2, 3],
  "regions": [ { "vertexIndices": [0,1,4,5], "fill": "#D6F0E0",
                 "label": "색칠한 부분" } ],
  "splitLines": [ { "from": 1, "to": 4, "style": "dashed" } ]
}

규칙:
- 좌표는 **비율만 맞으면 된다.** 가로 10·세로 4면 [[0,0],[10,0],[10,4],[0,4]].
  실제 cm를 좌표로 쓰지 마라 — 길이는 showLengths의 value로 간다.
- value는 단위까지 그대로("10cm", "x+6", "2b").
- 색칠한 부분은 regions로. 색을 지어내지 말고 `#D6F0E0` 하나만 쓴다.
- 직사각형·사다리꼴처럼 이름이 있는 도형이면 type을 "quadrilateral"로 하고
  preset("rectangle"·"trapezoid")을 쓰는 편이 낫다.
```

### P6. 입체도형 (0148)

```
<P0>

이 그림은 입체도형이다.

{
  "type": "solid",
  "shape": "cube" | "cylinder" | "cone" | "sphere" | "prism" | "pyramid",
  "dimensions": { "width": 120, "depth": 60, "height": 90 },
  "showDimensions": true,
  "labels": [ { "text": "120 cm", "position": [x, y] } ]
}

규칙:
- 직육면체는 shape "prism"에 width·depth·height를 준다.
- 안에 채운 작은 정육면체(벽돌)는 **그리지 않는다.** 개수를 세는 것이
  문제인데 그림에 다 그려 주면 답이 보인다. 지면도 그렇게 하지 않는다.
```

### P7. 어려운 그림 — inline SVG를 허락하는 경우 (0959 0960 1118)

여기서만 spec을 포기한다. 그릇 모양·타는 초·용수철은 프리셋이 없다.

```
너는 중학교 수학 교재의 그림을 **inline SVG**로 다시 그린다.
아래 규칙은 실제 운영에서 나온 것이다. 하나라도 어기면 화면이 깨진다.

1. `<svg viewBox="0 0 W H" xmlns="http://www.w3.org/2000/svg">`로 시작한다.
   width·height 속성은 쓰지 마라 — 화면 폭에 맞춰 늘어나야 한다.
2. viewBox는 여유 있게 잡는다(그림 하나면 240×180 이상, 두 개를 나란히
   놓으면 500 이상). 라벨이 잘리는 것이 가장 흔한 사고다.
3. 글자는 전부
   `<text font-family="Times New Roman, serif" font-style="italic" font-size="14">`.
   빽빽한 그림은 11~13. **라벨의 사각형이 선·곡선·다른 라벨과 닿지 않게**
   자리를 잡아라.
4. 색은 검정 선(#333)과 채움 하나(#D6F0E0)만 쓴다. 교재는 흑백이다.
