# ADR-0019 — 서버 함수는 DB와 같은 지역에서 돈다

| 항목 | 값 |
|---|---|
| 상태 | **채택됨** (2026-08-05) |
| 결정자 | 수맥 팀 |
| 관련 | `apps/web/vercel.json` · `packages/db/src/client.ts` · `apps/web/test/ui/deploy-region.test.ts` |

---

## 맥락

화면이 느리다는 말이 나와 재 봤다. 재고 나니 원인이 코드가 아니었다.

프로덕션 응답 헤더가 그대로 말해 준다.

```
X-Vercel-Id: icn1::iad1::…
             ↑     ↑
          엣지 서울  함수 버지니아
```

요청은 서울 엣지로 들어오는데 **서버 컴포넌트는 미국 버지니아(iad1)에서 돌고 있었다.** Supabase는 서울(`aws-1-ap-northeast-2`)이다. 그래서 질의 한 번마다 태평양을 왕복했다.

실측 (2026-08-05, 데모 조직):

| 화면 | 로컬 (서울↔서울) | 프로덕션 (버지니아↔서울) | 질의 수 | DB 실행 시간 |
|---|---|---|---|---|
| `/app/readiness` | 804ms | **11,260ms** | 47 | **13ms** |
| `/learn/today` | 541ms | **8,527ms** | 31 | 594ms |
| `/learn/blank` | 435ms | **7,445ms** | 17 | 1ms |
| `/app/setup` (제일 가벼움) | 132ms | **1,040ms** | 2 | 0ms |

`/app/readiness`의 11.26초 중 **DB가 실제로 일한 시간은 13밀리초**다. 나머지 99.9%는 왕복 지연이다. 질의 하나당 약 220ms — 거리가 곧 비용이다.

이 구조에서는 **질의를 하나 더 쓰는 일이 곧 220ms**다. 아무리 가벼운 질의여도 그렇다. 코드를 아무리 다듬어도 이 상수를 이길 수 없다.

## 결정

**서버 함수 지역을 DB 지역에 맞춘다 — `icn1`(서울).**

두 곳에 적는다. 한 곳만 적으면 다른 한 곳이 조용히 되돌린다.

1. **`apps/web/vercel.json`의 `regions`** — 저장소 안에 있어 코드리뷰에 걸리고, 프로젝트를 다시 만들어도 따라온다.
2. **Vercel 프로젝트 설정 `serverlessFunctionRegion`** — 이미 존재하는 배포에 적용된다.

### Hobby 플랜에서도 된다

대시보드에는 지역 선택이 **안 보인다.** 그래서 "Hobby는 iad1 고정"으로 읽기 쉽고, 실제로 그렇게 알려져 있다. 하지만 API로는 바뀐다:

```
PATCH /v9/projects/{name}  {"serverlessFunctionRegion":"icn1"}
```

바꾼 뒤 배포하면 배포 메타데이터가 `regions: ['icn1']`로 나온다. **플랜을 올릴 이유도, 프로젝트를 지우고 다시 만들 이유도 없다.**

### 되돌아가는 것을 막는다

이 설정은 조용히 사라진다 — 프로젝트를 다시 만들거나, 대시보드에서 초기화하거나, `vercel.json`을 지우면 그만이다. 그리고 사라져도 **아무 에러가 없다.** 화면이 14배 느려질 뿐이고, 그건 "원래 좀 느리네"로 넘어간다.

그래서 `apps/web/test/ui/deploy-region.test.ts`가 `vercel.json`의 지역이 DB 지역과 짝이 맞는지 본다. 파일이 사라지거나 지역이 갈리면 테스트가 빨개진다.

## 결과

- 지역을 맞추면 질의당 비용이 220ms → 20ms 아래로 떨어진다. 화면 코드는 한 줄도 바뀌지 않는다.
- **질의 수를 줄이는 일이 그래도 의미 없어지지는 않는다.** 서울에서도 왕복은 왕복이다 — `/app/readiness`는 학생마다 투영기를 줄 세우고 있었고, 겹쳐 돌리자 841ms → 201ms(76% 감소)가 됐다. 지역이 상수를 낮추고, 왕복 횟수가 배수를 낮춘다. 둘은 곱해진다.
- DB를 다른 지역으로 옮기면 이 ADR을 다시 열어야 한다. 짝이 맞는 것이 조건이지 `icn1`이 조건이 아니다.

## 대안과 기각 이유

**Vercel Pro로 올린다** — 필요 없다. Hobby에서도 API로 바뀌는 것을 확인했다. 돈이 드는 답을 먼저 고르지 않는다.

**프로젝트를 지우고 서울로 다시 만든다** — 새로 만들어도 기본값은 `iad1`이다. 같은 자리로 돌아온다.

**DB를 미국으로 옮긴다** — 사용자가 한국에 있다. 브라우저↔서버 왕복이 대신 느려질 뿐이고, 그 왕복은 화면당 여러 번이 아니라 한 번이라 지금 문제만큼 크지는 않지만, 학생이 답을 제출할 때마다 태평양을 건너게 된다.

**엣지 런타임으로 옮긴다** — 서버 컴포넌트가 postgres.js(TCP)를 쓴다. 엣지에서는 못 쓴다. 드라이버를 HTTP 기반으로 바꾸는 것은 이 문제를 풀자고 치르기엔 큰 값이다.
