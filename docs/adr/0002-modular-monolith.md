# ADR-0002 — 모듈형 모놀리스와 서비스 분리 기준

| 항목 | 값 |
|---|---|

| 관련 | [architecture.md](../phase0/architecture.md) · [domain-map.md](../phase0/domain-map.md) · [ADR-0010](./0010-job-queue-and-ai-abstraction.md) |

## 맥락

수맥은 9개 도메인 컨텍스트를 가진다. 이 중 일부는 자원 특성이 명백히 다르다.

| 컨텍스트 | 자원 특성 |
|---|---|
| 응시·채점 | 짧고 잦은 쓰기. 피크 875 RPS |
| 수학 표현·출력 | Chromium CPU 독점. 건당 45ms |
| 교육과정·콘텐츠 | 외부 AI 호출 대기. 건당 수 초~수십 초 |
| 학습 경로·계획 | CPU 집약 계산. 건당 수 초~수십 초 |

동시에 **강한 트랜잭션 관계**가 있는 영역도 명확하다. 루트 게시 → 수업 생성 → 평가 게시 → 응시 → 채점 → 숙련도는 [state-machines.md](../phase0/state-machines.md)의 불변 조건으로 묶여 있고, 골프롬프트 2D의 "강한 일관성" 목록 10개가 전부 이 사슬 안에 있다.

마이크로서비스로 나누면 이 사슬이 분산 트랜잭션 또는 사가가 된다. 예를 들어 "평가 문항 스냅샷 생성과 평가 게시"를 원자적으로 하려면 문항 서비스와 평가 서비스가 2PC를 하거나, 보상 트랜잭션으로 스냅샷을 되돌려야 한다. 후자는 **불변 조건 I-08(게시된 평가는 스냅샷)** 을 지키기 어렵게 만든다.

반대로 전부 한 프로세스에 넣으면 대량 OCR이 답안 제출 지연을 만든다. 골프롬프트 28장은 "실시간 채점이 대량 OCR보다 높은 우선순위"를 요구한다.

## 결정

**도메인 경계가 명확한 모듈형 모놀리스. 배포 단위는 `apps/web`과 `apps/worker` 2개. 데이터는 단일 PostgreSQL.**

### 1. 프로세스 분리 ≠ 데이터 분리

이 둘을 구분한다.

| | 프로세스 분리 | 서비스 분리 |
|---|---|---|
| 의미 | 다른 프로세스로 실행·확장 | 다른 서비스가 **데이터를 소유** |
| 수맥 현재 | **적용** (web / worker, 큐별 워커) | **미적용** |
| 트랜잭션 | 같은 DB, 같은 트랜잭션 가능 | 분산 트랜잭션 또는 사가 필요 |
| 되돌리기 | 쉬움 (같은 코드베이스) | 어려움 (스키마 분리 후) |

### 2. 배포 단위 (확정)

| 단위 | 프로세스 | 확장 |
|---|---|---|
| `apps/web` | Next.js 16 | 수평(무상태). 인스턴스당 DB pool max 10 |
| `apps/worker:realtime+schedule` | tsx | 2 vCPU × 2 |
| `apps/worker:render` | tsx + Chromium | 4 vCPU × 2 |
| `apps/worker:ai+default` | tsx | 2 vCPU × 2 |

worker는 **환경변수 `WORKER_QUEUES`로 담당 큐를 지정**한다. 같은 이미지, 다른 설정. 큐 조합을 바꾸는 데 코드 변경이 필요 없다.

### 3. 모듈 경계 강제 (코드 레벨)

경계가 문서에만 있으면 6개월 뒤 사라진다. 도구로 강제한다.

| # | 규칙 | 도구 |
|---|---|---|
| B-1 | `features/<X>/server/**`는 `features/<Y>/server/{queries,actions}`만 import. `internal/**` 금지 | `eslint-plugin-boundaries` |
| B-2 | `packages/db/src/schema/<Y>.ts`는 소유 컨텍스트 feature에서만 직접 import | 동일 |
| B-3 | `packages/core/**`는 `packages/db`·`apps/**`를 import 불가 | 동일 |
| B-4 | `apps/worker/**`와 `apps/web/**`는 서로 import 불가 | 동일 |
| B-5 | 명령은 `defineCommand()` 래퍼 없이 쓰기 불가 (멱등성·잠금·감사 강제) | 타입 시스템 |
| B-6 | 다른 컨텍스트의 명령을 같은 트랜잭션에서 호출 금지 | 트랜잭션 러너가 컨텍스트 태그 검사 |

### 4. 서비스 분리 기준 (6조건 중 2개 이상, 실측)

| # | 조건 | 측정 지표 | 임계값 |
|---|---|---|---|
| S-1 | 현저히 다른 확장·자원 특성 | 큐별 CPU-초/요청, 메모리 상주 | 특정 큐가 전체 워커 CPU의 60% 이상을 **30일 연속** 점유 |
| S-2 | 반드시 격리해야 하는 장애 영향 | 해당 모듈 장애로 인한 타 모듈 SLO 위반 | **90일 내 3회 이상** |
| S-3 | 독립 런타임(Python·GPU)의 지속적 필요 | 대체 불가 기능 수 | **2개 이상이 6개월 이상** |
| S-4 | 별도 보안·데이터 지역·배포 주기 | 계약·규제 문서 | 요구 발생 시 **즉시** |
| S-5 | 독립 소유 팀과 안정된 공개 계약 | 팀 수, 계약 변경 빈도 | 전담 팀 2개 이상 + 계약 6개월 무변경 |
| S-6 | 단일 DB로 해결 불가한 실측 병목 | p99 지연, 락 대기, IO 포화 | 파티션·인덱스·풀 튜닝 후에도 SLO 미달 **30일 지속** |

**"측정으로 확인"이 조건이다.** 예측·직감은 조건 충족이 아니다. 조건 충족을 주장하려면 30일 이상의 지표 데이터를 이 ADR에 첨부해야 한다.

### 5. 분리 후보와 소유 데이터 (조건 충족 시)

| 순위 | 후보 | 예상 조건 | 소유 데이터 | 계약 |
|---|---|---|---|---|
| 1 | 콘텐츠 반입 OCR·AI 워커 | S-1, S-3 | `source_files`, `source_pages`, 추출 중간 산출물 | 작업 등록 API + `ContentApproved` |
| 2 | 문서 출력 워커 | S-1 | `document_exports` (메타는 코어 유지) | 작업 등록 API + `RenderArtifactValidated` |
| 3 | 알림 워커 | S-2 | 없음 (읽기만) | Outbox 소비만 |
| 4 | 대용량 리포트 워커 | S-1 | 없음 | 작업 등록 API |

**분리하지 않는 영역(불변)**: 루트 게시, 실제 수업 생성·충돌 확정, 평가 게시·스냅샷, 응시·답안·채점 확정. S-6이 증명되어도 먼저 파티셔닝·수직 확장을 시도한다.

### 6. 분리를 쉽게 만드는 사전 준비

지금 분리하지 않되, 나중에 분리할 수 있게 둔다.

| # | 준비 |
|---|---|
| 1 | 컨텍스트마다 **공개 조회·명령 인터페이스**가 이미 존재 ([domain-map.md](../phase0/domain-map.md) 3.3·3.4) |
| 2 | 반환 타입이 ORM 엔티티가 아니라 **readonly DTO** — 스키마 결합 없음 |
| 3 | 컨텍스트 간 통신이 **3가지 수단**(조회·명령·이벤트)으로만 제한 |
| 4 | 이벤트 페이로드가 이미 **최소 필드**로 자족적 |
| 5 | 스키마 파일이 컨텍스트별로 분리 (`packages/db/src/schema/<context>.ts`) |
| 6 | 큐가 이미 컨텍스트 단위로 나뉘어 있음 |

분리 시 필요한 작업은 ① 스키마를 별도 DB로 이동 ② 조회·명령 인터페이스를 HTTP로 감싸기 ③ 강한 일관성 요구가 있으면 이벤트로 재설계. ①~②는 기계적이다.

## 대안

| 대안 | 장점 | 채택하지 않은 이유 |
|---|---|---|
| **A. 단일 프로세스 모놀리스** | 가장 단순. 배포 1개 | 대량 OCR이 답안 제출을 지연시킨다. Chromium이 4 vCPU를 점유하면 요청 처리가 굶는다. 골프롬프트 28장 우선순위 요구 위반 |
| **B. 처음부터 마이크로서비스** | 팀 확장·독립 배포 | ① 강한 일관성 10개 항목이 전부 분산 트랜잭션이 된다 ② 팀이 1개인데 서비스가 5개면 운영 부담만 늘어난다 ③ 실측 병목이 없는데 나누면 잘못된 경계로 나눌 확률이 높다 ④ 골프롬프트 2B가 명시적으로 "과도하게 분산하지 않되 나중에 분리할 수 있도록" 요구 |
| **C. 함수형 서버리스** | 자동 확장, 유휴 비용 0 | ① 장시간 작업(OCR 20분, PDF 렌더)이 실행 시간 제한에 걸린다 ② Chromium 콜드 스타트 1.8초 ③ DB 커넥션 폭증 ④ 워커 lease·SKIP LOCKED 모델과 맞지 않음 |
| **D. web + worker를 같은 프로세스, 스레드로 분리** | 배포 1개 유지 | Node.js 워커 스레드는 Chromium·네이티브 모듈과 궁합이 나쁘다. 메모리 격리도 약하다. 배포 단위를 나눈 비용이 크지 않다 |
| **E. 데이터베이스도 컨텍스트별 분리 (같은 프로세스)** | 나중 분리가 쉬움 | 강한 일관성 트랜잭션이 즉시 불가능해진다. 얻는 것 없이 잃는다 |

## 비용

| 항목 | 비용 |
|---|---|
| 배포 복잡도 | 배포 단위 4개(web + 워커 3종). 단일 프로세스 대비 +3 |
| 인프라 | 워커 상시 프로세스 6개(2 vCPU×4 + 4 vCPU×2). 월 약 USD 380 |
| 개발 | 경계 규칙 학습, ESLint 설정, 인터페이스 작성 오버헤드 |
| 관측 | 큐별·컨텍스트별 지표를 따로 봐야 함 |
| 미래 부채 | 분리가 필요해지면 그때 비용이 발생. 사전 준비(6절)로 완화 |

## 실패 방식

| # | 어떻게 실패하는가 | 조기 신호 | 대응 |
|---|---|---|---|
| F-1 | 경계가 서서히 무너져 "분산 모놀리스"가 됨 | ESLint 경계 위반 예외 주석 증가 | 예외 주석에 만료일 필수. 만료 시 CI 실패 |
| F-2 | 컨텍스트 간 동기 호출 사슬이 길어져 지연 누적 | 명령 p95 > 800ms, 트레이스 깊이 > 5 | 트레이스 깊이 알림. 이벤트로 재설계 |
| F-3 | 워커 큐 하나가 DB 커넥션을 독점 | `db_connection_saturation` | 큐별 커넥션 풀 상한 |
| F-4 | "나중에 분리하면 되지"로 성능 문제를 미룸 | SLO 위반이 30일 지속 | S-6 조건이 발동. 하지만 먼저 파티션·인덱스를 시도 |
| F-5 | 조건 미충족인데 분리를 강행 | 이 ADR에 지표 데이터 없이 분리 제안 | ADR 갱신 없이는 분리 불가 |
| F-6 | 반대로, 조건 충족인데 계속 미룸 | S-2 발동(90일 3회 SLO 위반) | 분기 아키텍처 리뷰에서 6조건 점검 필수 |

## 되돌리기

| 방향 | 방법 | 비용 |
|---|---|---|
| 워커 3종 → 1종 통합 | `WORKER_QUEUES` 환경변수 하나로 합침 | **거의 0** (설정만) |
| web + worker → 단일 프로세스 | worker 루프를 web 프로세스에서 기동. 코드 공유 중이라 가능 | 낮음 (반나절) |
| 서비스 분리 → 모놀리스 복귀 | 분리한 적이 없으므로 해당 없음 | — |
| 모듈 경계 완화 | ESLint 규칙 제거. **권장하지 않음** | 낮지만 되돌리기 어려운 방향 |

가장 되돌리기 쉬운 축(프로세스)만 지금 나누고, 가장 되돌리기 어려운 축(데이터 소유)은 나누지 않는다. 이것이 이 결정의 핵심이다.
