# 수락 매트릭스 — 학생 자율형 하루 수업

> 기준일: 2026-08-04 · 출처: `docs/planning/06-tasks.md` T0.3 · 근거: [ADR-0017](../adr/0017-learner-day-and-session-completion.md), [ADR-0018](../adr/0018-daily-plan-projection-and-assessment-scheduler.md)

「핵심 완료 시나리오」 10단계를 실행 가능한 Given/When/Then으로 옮긴 것이다. **T6.2의 `e2e/tests/autonomous-day.spec.ts`가 이 표를 그대로 구현한다.**

## 1. 시나리오 수락 조건

각 항목의 `검증`은 화면 문구가 아니라 **DB 상태 또는 이벤트**를 본다. 화면만 보면 서버에 아무것도 안 남아도 통과한다 — 그것이 지금 고치려는 결손(G-02)이다.

### A-01. 빈 워크스페이스에서 반·학생·계정 만들기

| | |
|---|---|
| **Given** | 새 조직에 과정 기간·반·학생·학생 계정이 하나도 없다 |
| **When** | 권한 있는 사용자가 `/app/setup`의 단계를 따라 기간 → 반 → 학생 → 로그인 계정을 만든다 |
| **Then** | `course_periods`·`learning_groups`·`learners`·`learning_group_memberships` 각 1건 이상, 학생이 자기 계정으로 로그인해 `/learn/today`에 도달 |
| **검증** | 시드 스크립트·수동 SQL을 **한 번도 쓰지 않는다.** `pnpm db:seed`가 호출되면 실패 |
| 태스크 | T5.1, T5.2 |

### A-02. 8종 노드를 가진 루트 만들기

| | |
|---|---|
| **Given** | A-01의 반이 있고 루트가 없다 |
| **When** | 담당 교사가 개념·교재 범위·읽기·영상·연습·숙제·일일테스트·확인테스트 노드를 가진 루트를 만든다 |
| **Then** | `route_nodes`에 8종이 모두 저장되고, 각 노드의 payload 필수 필드가 채워짐 |
| **검증** | `daily_test` 노드가 **폼에서 도달 가능**해야 한다 — 현재 `RouteBuilderForms.tsx:95-104`에 없다(G-05) |
| 태스크 | T2.1 |

### A-03. 준비도 검증이 결손을 게시 전에 막는다

| | |
|---|---|
| **Given** | 루트에 문항 0개 연습 자료, 미게시 자료, 계정 미연결 학생, 평가 정책 없음이 섞여 있다 |
| **When** | 교사가 루트 게시를 시도한다 |
| **Then** | 게시가 차단되고 결손 목록이 **문제 화면과 복구 행동**을 함께 안내한다. 선택 항목 결손은 경고로만 남는다 |
| **검증** | 차단 사유 코드가 학생 화면의 `blocked_reason`과 **같은 레지스트리**를 쓴다 (ADR-0017 §2) |
| 태스크 | T2.4 |

### A-04. 워커가 날짜별 평가를 자동 생성한다

| | |
|---|---|
| **Given** | 루트가 게시되어 미래 `sessions`가 생성됐고, 교사는 **평가 생성 버튼을 누르지 않는다** |
| **When** | 설정된 선행 시점(`generate_before_hours`)이 지나고 워커가 돈다 |
| **Then** | `assessment_instances`가 `published`로 생성되고 `assignments`가 학생별로 배정됨 |
| **검증** | 스펙 전체에서 평가 생성 버튼 클릭이 **0회**. 실제 워커 프로세스가 떠 있어야 한다(`playwright.worker.config.ts`) |
| 태스크 | T3.2, T3.3 |

### A-05. 학생에게 오늘 것만 보인다

| | |
|---|---|
| **Given** | 학생에게 ① 91일 전 완료 테스트 ② 89일 전 완료 테스트 ③ 오늘 배정 ④ 내일 배정이 있다 |
| **When** | 학생이 로그인해 `/learn/today`를 연다 |
| **Then** | 오늘 필수 항목만 순서대로 보이고, ①②는 완료 판정에 **영향이 없으며**, ④는 「예정」으로만 보이고 분모에 들어가지 않는다 |
| **검증** | `learner_day_plans` 1건 생성(`materialized_at` 설정), `learner_day_plan_items`의 `required` 합이 ③만 셈 |
| 태스크 | T1.3, T1.4 |

### A-06. 필수 항목을 다 끝내면 서버에 확정된다

| | |
|---|---|
| **Given** | A-05의 하루 계획에 미완료 필수 항목이 남아 있다 |
| **When** | 학생이 자료·연습·테스트·복습을 모두 끝낸다 |
| **Then** | `learner_day_plans.status='completed'` + `completed_at` 설정 + `outbox_events`에 `LearnerDayCompleted` **정확히 1건** |
| **검증** | 새로고침·재클릭·중복 제출 후에도 outbox 1건. `sessions.status`는 **변하지 않는다**(`I-21`) |
| 태스크 | T4.1 |

### A-07. 교사가 학생별 상태와 막힘 사유를 본다

| | |
|---|---|
| **Given** | 반에 완료 학생, 진행 중 학생, 차단 학생, 미시작 학생이 각 1명 이상 |
| **When** | 교사가 `/app/today` 또는 반 상세를 연다 |
| **Then** | 네 상태가 구분되어 보이고, 차단 학생은 **사유가 자료·문항·계정·워커 중 무엇인지** 표시됨 |
| **검증** | 표시값이 `learner_day_plans.status`·`learner_day_plan_items.blocked_reason`에서 옴. 마이그레이션 이전 날짜는 `no_record`로 구분(ADR-0018 §6) |
| 태스크 | T4.4 |

### A-08. 교사 마감이 진도와 이벤트를 같은 트랜잭션에 남긴다

| | |
|---|---|
| **Given** | 반 학생 일부만 하루를 완료했다 |
| **When** | 교사가 실제 진행 범위를 확인해 수업을 마감한다 |
| **Then** | `sessions.status='completed'` + `progress_events` INSERT + `SessionCompleted` outbox가 **한 트랜잭션** |
| **검증** | 전원 완료여도 **자동 마감되지 않는다**(기본값). 마감 재시도는 1회 전이로 끝남 |
| 태스크 | T4.2 |

### A-09. 완료와 숙련도가 미래 일정 변경안이 된다

| | |
|---|---|
| **Given** | A-08의 마감에 미진행 노드가 있고, 학생 중 한 명에게 불참 이벤트가 있다 |
| **When** | `planning-engine`이 `SessionCompleted`·`LearnerDayCompleted`·`LearningAvailabilityChanged`를 소비한다 |
| **Then** | 미진행 노드가 다음 가용 슬롯으로 이동한 변경안이 생기고, **고위험 변경은 승인 전 적용되지 않는다** |
| **검증** | 승인 전 `sessions` 행의 시각이 변하지 않음. 과거·완료·잠금 일정 불변(`I-05`) |
| 태스크 | T4.3 |

### A-10. 중단·중복·재시도에도 결과가 역행하지 않는다

| | |
|---|---|
| **Given** | 워커를 A-04 도중에 죽였다가 되살린다 |
| **When** | 같은 학생 완료 10회, 같은 반 평가 생성 10회, 교사 마감 2회를 동시에 시도한다 |
| **Then** | 평가 1건, 완료 이벤트 1건, 마감 1회. 누락 없음 |
| **검증** | **G-15 선행**: 인덱스 수리 전에는 반 공통 평가가 중복 생성된다 — 이 항목이 그것을 잡는 그물이다 |
| 태스크 | T3.2, T6.3 |

## 2. 실패 상태 매트릭스

각 실패에서 **학생이 무엇을 보는지**와 **교사가 무엇을 하면 풀리는지**가 둘 다 정의돼야 한다. 한쪽만 있으면 학생은 영원히 기다리거나 교사는 원인을 모른다.

| 상태 | 학생 화면 | 하루 판정 | 교사 화면 | 복구 행동 |
|---|---|---|---|---|
| **빈 날** (계획 항목 0) | 「오늘은 예정된 학습이 없습니다」 | `empty` — 완료도 미완료도 아님 | 해당 날짜에 학생 없음 | 없음 (정상) |
| **수업만 있는 날** (자료·평가 없는 노드) | 수업 안내만, 완료 버튼 없음 | 필수 0건 → `empty` | 「자료 없는 차시」로 표시 | 필요하면 자료 연결 |
| **자료 부족** (노드에 자료 미연결) | 해당 항목 `blocked`, 「선생님께 알려 주세요」 | 완료 불가 | 준비도에 `material_missing` | 자료 연결 후 재투영 |
| **문항 부족** (연습 자료 0문항) | 항목 `blocked`, 사유 표시 | 완료 불가 | 준비도에 `no_questions` + 게시 차단 | 문항 추가 또는 항목 비필수화 |
| **평가 생성 실패** | 테스트 항목 `blocked`, 사유 `assessment_generation_failed` | 완료 불가 | 업무함에 E-17 알림 + `recovery_href` | `/app/tests`에서 재실행(같은 멱등 키) |
| **워커 중단** | 그 시점까지 생성된 것만 보임 | 미생성 항목이 없으므로 **분모에 안 듦** | 준비도에 「생성 지연」 | 워커 재기동 → 보존된 작업 실행 |
| **계정 미연결** | 로그인 불가 또는 「학습자 정보가 연결되지 않았습니다」 | 계획 없음 | 준비도에 `account_unlinked` | 계정 발급·연결 (T5.2) |
| **권한 만료 교재** | 해당 항목 `blocked` | 완료 불가 | 준비도에 `rights_expired` | 사용권 갱신 또는 대체 자료 |
| **학생 일부 미완료** | 각자 자기 상태 | 학생별로 다름 | 반 현황에 완료/진행/막힘/미시작 | 마감 여부는 교사 판단 |

**공통 원칙**: `blocked`는 완료를 막지만 **선택 항목의 `blocked`는 막지 않는다**(ADR-0017 §3). 그리고 어떤 실패도 **성공처럼 게시·배정되지 않는다**.

## 3. 격리와 정리 전략

기존 E2E는 데모 조직(`00000000-0000-7000-8000-000000000001`)과 데모 계정(`demo-teacher@`/`demo-student@`)을 쓴다. **T6.2는 그럴 수 없다** — A-01이 "빈 워크스페이스에서 시작"을 요구하기 때문이다.

| 항목 | 결정 |
|---|---|
| 조직 | **실행마다 새 조직**을 만든다. 데모 조직을 건드리지 않는다 |
| 계정 | 실행마다 새 이메일(`e2e-{runId}-teacher@…`). `e2e/lib/accounts.ts`의 데모 계정을 재사용하지 않는다 |
| 사람 확인용 계정 | `st2000423`·`st2000424`는 **절대 건드리지 않는다** — `accounts.ts` 주석의 원칙 그대로 |
| 날짜 | 오늘(KST) 고정. 브라우저 시계를 조작하지 않는다(공통 규칙) |
| 정리 | 티어다운에서 `purgeTestData(sql, <그 실행의 org>)`. 데모 조직 인자를 넘기지 않는다 |
| 불변 증거 | 응시·채점이 생긴 학습자는 `purgeTestData`가 **삭제하지 않고 보관 처리**한다 — 정상이며, 실행마다 조직이 달라 누적이 다음 실행에 섞이지 않는다 |
| 잔여 조직 행 | 조직 자체는 남는다. 누적이 문제가 되면 별도 배치로 정리한다(T6.2 REFACTOR에서 판단) |

**금지**: 데모 조직에 대고 `pnpm purge:test-data`를 도는 것으로 T6.2를 격리했다고 보지 않는다. 그 조직에는 사람이 손으로 확인하는 데이터가 있다.

## 4. 기존 E2E와의 경계

| | `full-loop.spec.ts` (기존) | `autonomous-day.spec.ts` (T6.2) |
|---|---|---|
| 시작점 | 시드된 데모 조직·학생·평가 | **빈 조직** |
| 평가 생성 | 시드가 이미 만들어 둠 | **워커가 만든다** |
| 워커 | 안 뜬다 | **실제로 뜬다** |
| 검증 대상 | 응시 → 채점 → 복습 → 교사 확인 | 설정 → 생성 → 학습 → 완료 → 마감 → 재계획 |
| 계정 | `TEACHER`/`STUDENT` 상수 | 실행마다 새로 발급 |

**기존 스펙을 지우지 않는다.** 둘은 다른 것을 지킨다 — `full-loop`은 채점·복습 순환을, `autonomous-day`는 하루 완결을 본다.

## 5. 모바일·접근성·실워커 검증 범위

| 범위 | 대상 | 명령 |
|---|---|---|
| 반응형 | A-05·A-06 학생 화면, A-07 교사 현황판 | `--project=desktop --project=tablet --project=mobile` |
| 접근성 | 새로 만드는 화면 전부 (`/learn/homework`, `/app/readiness`, `/app/setup`) | `e2e/tests/a11y.spec.ts`에 라우트 추가 |
| 키보드 | A-05 → A-06 완주를 마우스 없이 | `autonomous-day.spec.ts` 안의 키보드 전용 경로 |
| 실워커 | A-04·A-10 | `e2e/playwright.worker.config.ts`의 `webServer`가 웹과 워커를 함께 띄움 |
| 안정성 | A-01~A-10 전체 | `--repeat-each=5` 5/5 통과 |

접근성 기준은 WCAG 2.0 A/AA 자동 검사(axe) 위반 **0건**이며, 360px에서 가로 스크롤이 생기지 않아야 한다.

## 6. 이 매트릭스가 덮지 않는 것

- 출결 ERP·보호자 CRM·상담·수납 (제품 경계 밖 — `scripts/boundary-check.mjs`가 강제)
- 숙제 파일 업로드·자유 서술 제출 (MVP 비범위 — 교재 범위 확인 또는 시스템 연습만)
- 밀린 항목의 교사 승격 (ADR-0017 §5에서 M4 이후로 미룸)
- 자동 마감 UI (ADR-0017 §1에서 기본 꺼짐, MVP 미노출)
